# v0.5 live pilot results

The five-launch live pilot produced three approved task completions, one
unsuccessful completion attempt after repeated malformed router responses,
and one successful deliberate interruption check. All four implementation
patches met their original examples, allowed file scope, and fresh independent
test/lint checks. Passing checks did not turn the unsuccessful run into an
approved completion.

Collection used the frozen [protocol](v0.5-live-protocol.md) on
2026-10-22, 16:51:16–16:57:39 UTC, with the first-pass lint deviation recorded
below. No failed observation was replaced and no extra live cohort was
launched. The terminal experience and enforcement worked
in these observations; live routing remains dependent on manual decisions and
explicit recovery. This is a functional smoke pilot, not a general reliability
or performance result, and it does not claim every live run completed.

## Failure, repair, and interruption evidence

Jev returned rejected distributions totaling approximately 0.99 at r02
iteration 1, r03 iterations 1 and 6, and r04 iteration 3. The existing 0.001
tolerance rejected all four. r02, r03, and r04 each received the protocol's one
explicit recovery. On r03's second failure the operator selected stop, as
specified before collection. It exited 1 with `evaluation_failed`, retaining
its correct patch and passing generation-1 checks. No probabilities were
renormalized, confidence increased, provider/worker switched, or failed
evaluation used to authorize an action. Failure and recovery trace records
are deduplicated by iteration in reporting; they are not extra evaluations.

In r04 the first Codex call changed only `label.test.mjs`, preserving the
original implementation and long-label case while adding the three required
regressions. The separately approved test failed on the actual empty-label
bug. A second approved Codex call repaired the implementation without changing
those regressions. Fresh test and lint passed in generation 2 at iterations 6
and 7, followed by accepted completion at iteration 8. The ordinary worker
route was sufficient; this observation does not exercise the high-testing
repair-policy exception.

r04 did not run lint between its first failed test and the second worker call.
The protocol requested test and lint after every worker attempt, so this is a
procedural deviation. Generation-1 lint stayed pending and was never counted
as passing. Both required checks ran and passed in generation 2 before
completion; validation requirements and approval enforcement were preserved.

In r05 Ctrl+C at the first real approval prompt stopped the CLI with exit 130.
Its trace retained zero approvals, worker calls, or validations, and Git stayed
clean. All five process records show identical terminal flags before and after
the CLI. Styled progress/review/recovery and plain reviews retained the
separate resolved-candidate, validation, and completion approvals. The live
interruption case covered a prompt; active-worker cancellation remains covered
by the earlier deterministic and synthetic terminal checks.

The pilot supports working live worker integration and terminal interaction
within this scope, including controlled repair and safe failure. The repeated
malformed Jev responses are a release limitation, not a presentation failure
or evidence of improved routing quality. Native Windows live workers, other
live router routes, linked-issue preparation, real active-worker cancellation,
and screen-reader behavior were not exercised by this cohort. Keep this mixed
outcome visible in release review; npm publication remains pending.
