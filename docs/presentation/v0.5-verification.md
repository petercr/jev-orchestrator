# v0.5 terminal verification

Third v0.5 deliverable, 2026-10-22: exercise the integrated CLI in real WSL
PTYs and native Windows ConPTY, then repeat against an independently installed
checkout archive. The [optional harness](../../scripts/terminal/README.md)
retains repeatable assertions and captures without adding runtime dependencies.
This remains unreleased work; the package version is still `0.4.0`.

## Presentation and enforcement

The matrix covers 33 scenarios per platform. Reviews at 40, 60, 80, and 120
columns preserve initial worker and validation parameters in full, including
absolute paths, spaces, Unicode, quoted task text, and permission settings.
Later nested context is compared against the fields retained by bounded
traces; a trace truncation marker is not treated as an original value.
Fixture repository paths span roughly 148–173 characters, rather than testing
filesystem maximum path lengths.

Plain TTYs, pipes, CI, `NO_COLOR`, and `TERM=dumb` produce no application ANSI
output. Static reviews retain named sections, complete parameters, text status
labels, typed choices, limits, and final validation evidence. This text review
does not rely on color, animation, or a highlighted default. Headless terminal
reconstruction checks actual wrapping and cursor movement; it is not a GUI
font or screen-reader certification.

The real policy and approval loop retain explicit recovery, separately
confirmed alternatives, completion acceptance after fresh independent checks,
current-generation repair, immutable worker/network selection, and existing
budgets. Both adapters and explicit Codex networking are exercised. Invalid
input approves nothing, and eight rejections exhaust the iteration budget
without a worker call.

EOF, timeout, and signals are exercised at approval, clarification, and
recovery prompts. Escape and EOF during resolved completion approval stop
without inventing approval or acceptance. Active evaluation and worker
interruption retain conventional exits and bounded evidence. POSIX execution
also checks a TERM-resistant descendant and SIGTERM; Windows checks direct
child cancellation through Ctrl+C. Partial edits remain, validation is not
claimed, and fixture worker processes are checked dead before driver cleanup.

POSIX terminal flags, both platforms' raw-mode and cursor restoration, and
owned signal-listener cleanup are asserted. Application bytes are captured
before ConPTY's own VT encoding, so transport frames cannot be mistaken for
application styling. JSON and traces retain their existing schemas and contain
no renderer preferences, styling bytes, or configured synthetic credential.

## Finding and fix

Plain Windows console input delivered Ctrl+D/Ctrl+Z as a submitted control
line instead of closing stdin. The initial checks waited for input and failed
their deadline. The adapter now treats an otherwise empty EOF control line
from a TTY as `input_closed`, latches the closed-input state, and stops with
exit `1`. Plain mode remains line-oriented: Windows users press Enter after
the control key. Styled Ctrl+D remains immediate. Two focused cases cover both
keys, no raw-mode activation, no ANSI output, and rejection of later prompts.

The harness also exposed its own setup issues: the PTY driver initially
overrode `TERM=dumb`, screen comparison needed the displayed bidi escapes and
bounded trace truncation, and node-pty retained its Windows conout worker after
the CLI exited. These were corrected in verification tooling. Its pinned,
asserted driver cleanup is separate from application cleanup and is never
shipped. Earlier failing captures are retained.

Provider and worker boundaries are synthetic: the fixed TypeSafe endpoint is
intercepted, and Codex, Claude, and package-script launches become local Node
fixtures. Git inspection, the process runner, policy, approvals, independently

coding-agent service was called. Prompt timeout cases shorten only the test
timer, not the production 15-minute deadline. These results establish terminal
behavior with those boundaries, not live routing quality or native worker and
package-manager launcher availability.
