# v0.5 terminal presentation prototype

First v0.5 deliverable, 2026-10-21: compare Clack with the existing plain
presentation using the same synthetic action review, worker/check progress,
blocked run, and accepted-run summary. This is a checkout-only development
command. The published `dev-agent` interface remains v0.4.0.

This records the first delivery slice. The subsequent
[production integration](v0.5-integration.md) promotes Clack to a runtime
dependency and exercises the real approval loop; findings below describe the
prototype at its original checkpoint.

## Try it

```bash
pnpm prototype:ui
pnpm prototype:ui --renderer plain
pnpm prototype:ui --renderer clack --scenario review --interactive
```

The default renders all four scenes without asking for input. A normal terminal
uses Clack; pipes, CI, `TERM=dumb`, `NO_COLOR`, and explicit `--renderer plain`
use static plain output. Each scene is labeled synthetic. Timing, approvals,
validation, and completion in the fixtures are invented display data, never
observations from a real run. No provider, worker, repository tool, or trace
writer is invoked.

Use `--scenario review|progress|blocked|summary` to inspect one scene. The optional
`--interactive` exercise accepts typed `approve`, `reject`, `stop`, or `quit`
at the review prompt. Empty or invalid input stays unselected. A response only
records a demo choice. The remaining scenes, if shown, are separate fixtures.
Interactive preview requires a terminal; static preview works with closed stdin.

The plain review uses the existing `formatApprovalLines`; Clack groups the same
lines into notes. Both preserve the provider recommendation, policy outcome,
resolved candidate, full parameters, required checks, remaining budgets, and
operator guidance. The fixture also exposes Codex-only selection, workspace
write permissions, and disabled command networking. Summaries reuse the current
outcome and timing formatters. Production alternative selection and a second
resolved-candidate approval are part of the integration step, not this demo.

## Library decision

Choose **`@clack/prompts@1.8.1`** for the next integration. Its notes, session
header/footer, status messages, and typed text prompt fit this sequential CLI.
The plain formatter remains useful for accessibility and unattended output.
A persistent React dashboard is outside this slice.

The lockfile adds six development packages: Clack prompts/core, sisteransi,
fast-wrap-ansi, fast-string-width, and fast-string-truncated-width. They impose
no narrower Node requirement than our Node 22 floor. Runtime dependencies remain
unchanged. The prototype lives under `scripts/presentation`, is typechecked by
`pnpm check`, and is excluded by the package's existing allowlist. Production
integration would require explicitly promoting the selected library to a
runtime dependency.

## Terminal findings and integration constraints

- Notes wrap full JSON parameters and long paths at 40 columns. Status labels
  are kept short because Clack's log helpers do not wrap them like notes do.
- Use an explicit text response for approval. The demo supplies no initial or
  default value; blank input cannot choose approval. A highlighted select or
  default confirmation is unsuitable for authorizing an action.
- Wrap the library prompt with a fresh, short-lived AbortController. Forward
  the run signal only while the prompt is active, cancel on input end/close,
  Ctrl+D, or the bounded 60-second preview deadline, and remove all owned
  listeners/timers afterward. Late signals must not redraw an already completed
  prompt. A cancelled prompt is distinct from a typed response.
- Keep one input owner at a time. Styled mode must replace the existing
  readline interface rather than attach a second prompt reader beside it.
- Keep Ctrl+C/SIGINT and SIGTERM under the run controller. The WSL PTY checks
  confirm exits 130 and 143 during prompts and progress, with cursor visibility,
  echo, canonical input, and signal handling restored.
- **Avoid Clack's native spinner.** In 1.8.1 it calls the core `block` helper,
  which owns stdin and invokes `process.exit(0)` for a Ctrl+C key. A native
  spinner PTY probe reproduced exit 0. The demo uses Clack status logs with
  controller-owned progress delays, preserving exit 130 instead. An animated
  production indicator, if added, needs application-owned input and cleanup.
- Sanitize terminal escape sequences and control bytes before rendering notes;
  make bidirectional controls visible. Keep parameter values escaped and fully
  reviewable. Existing redaction remains in the shared formatters.

These are presentation constraints, not new authorization rules. Integration
must retain the existing approval parser, candidate checks, manual-alternative
review, completion acceptance, evaluation recovery, budgets, and independent
validation. Display helpers and library defaults cannot supply authorization.

## Verification and remaining work

The prototype has 27 deterministic tests covering both renderers, complete
review content, fixture immutability, long parameters, terminal injection,
static fallbacks, input validation, EOF/Ctrl+D, cancellation, timeout, and
listener cleanup. A subprocess smoke renders all scenes in an empty consumer
without writing files. No live credentials are required.

`pnpm check`, all 1,377 tests across 39 files (`pnpm test --maxWorkers=2`), the
production build, and schema-only environment validation passed. A local packed checkout excludes the prototype
sources and installs without Clack. All 66 compiled files match the published
v0.4.0 runtime; installed version/help and keyless mock checks passed. This is an
unreleased checkout archive, kept separately from the unchanged published
archive, with the existing package version retained for this development slice.

Thirteen PTY walkthroughs passed on WSL2/Linux
`6.18.33.2-microsoft-standard-WSL2`, Node 24.22.1, pnpm 11.19.0: both renderers,
40-column output, blank-then-explicit input, typed stop, Ctrl+D, Ctrl+C and
SIGTERM at the prompt and during progress, `NO_COLOR`, and CI fallback. Each
checked terminal input flags and cursor restoration. Raw captures, the probe,
and receipts are retained outside Git at
`/home/peterc/.cache/dev-ui-prototypes/v050-20261021`.

Only the first delivery step is complete. Next, place the chosen presentation
behind a narrow production CLI adapter and exercise the actual approval loop.
Native Windows consoles, more terminal widths, packed styled/plain interaction,
JSON/trace isolation, interrupted worker cleanup, and production EOF/recovery
behavior remain acceptance checks for the later integration steps. This
prototype does not establish those results.
