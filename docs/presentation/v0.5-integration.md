# v0.5 terminal presentation integration

Second v0.5 deliverable, 2026-10-21: the orchestration CLI now uses the Clack
presentation selected by the [offline prototype](v0.5-prototype.md). This is
unreleased checkout work. The package version remains `0.4.0`; no npm
publication or replacement of a published archive is part of this slice.

## Behavior

`src/cli/terminal.ts` owns the renderer and one input reader. Interactive
orchestration groups the run header, model recommendation, policy decision,
resolved candidate, evidence, operator choices, progress, and final summary.
Candidate parameters remain fully visible, including the approved worker's
file and network permissions. Notes wrap their contents; phase updates use
static notes, avoiding Clack's native spinner and its input/signal ownership.

`--plain`, non-TTY input/output, CI, `NO_COLOR`, and `TERM=dumb` select static
output. Plain input explicitly disables readline's terminal rendering so it
does not emit cursor controls even inside a TTY. Decision-only output remains
plain, and JSON does not initialize a renderer or reader. Clack `1.8.1` moves
from development to runtime dependencies, adding its existing six-package tree
to installed consumers without changing pinned versions or the Node 22 floor.

Both modes use the existing typed approval parser and final candidate checks.
There is no default answer. An alternative receives its own resolved-candidate
review and separate approval; task acceptance still requires completion
review. The adapter cannot change policy, budgets, worker selection, command
networking, or current-generation independent validation.

Each prompt has a private cancellation scope and a 15-minute deadline.
Blank/invalid responses retry. EOF/Ctrl+D, timeout, or library cancellation
stops with exit code `1` and no invented response. Typed `stop`/`quit` retains
exit `0`; the run controller retains SIGINT `130` and SIGTERM `143`, draining
active process cleanup and preserving partial edits. Prompt timers and owned
listeners are removed afterward; late aborts cannot redraw completed prompts.
Terminal text is credential-redacted before and after stripping control
sequences; bidirectional controls are visibly escaped.

## Trace compatibility

Decision-only JSON stays at schema version `1`; orchestration stays at version
`2`. An optional additive `promptStop: { phase, reason }` records only
`input_closed`, `input_timeout`, or `input_cancelled`. Existing signal evidence
remains `interruption: { phase, reason: "signal" }`. A missing response is not
an approval, clarification, recovery decision, or signal. A genuine earlier
approval remains recorded if a later clarification prompt closes. Styling
preferences and renderer objects never enter state, candidates, worker context,
or traces.

## Verification

All checks used synthetic provider/process boundaries, with no live model or
coding-agent calls:

- 79 focused adapter, integration, CLI argument, and signal tests passed.
  Real policy, candidate selection, execution normalization, and loop
  transitions cover both renderers, repair after failed validation, manual
  completion alternatives, and unanswered approval/clarification/recovery.
- `pnpm check`, all 1,404 tests across 41 files
  (`pnpm test --maxWorkers=2`), `pnpm build`, and
  `pnpm env:check:schema` passed.
- Eleven controlling-PTY walkthroughs each passed against the compiled CLI
  and an independently installed checkout archive: styled/plain completion,
  failed-check repair, evaluation recovery, styled/plain EOF, prompt Ctrl+C,
  active-worker SIGTERM, `NO_COLOR`, CI, and 40-column output. Disposable Git
  repositories, a fake Codex executable, and an intercepted TypeSafe endpoint
  exercised the actual CLI, approvals, process runner, trace writer, and
  independent `npm test` command. The interrupted worker retained its partial
  edit and invalid validation state. Checks asserted exit statuses, budgets,
  approval history, trace redaction, terminal input flags, and cursor restoration.
- The packed consumer installs pinned Clack as a runtime dependency, excludes
  prototype/source/test files, and passes installed executable version/help
  and keyless schema-v1 JSON checks. The initial package probe used a symlink
  module path that bypasses the CLI's existing direct-invocation guard; the
  successful check uses the installed executable, and PTYs use its resolved
  runtime path.

The WSL2 environment was Linux `6.18.33.2-microsoft-standard-WSL2`, Node
24.22.1, pnpm 11.19.0. Captures, fixtures, logs, and receipts are retained
