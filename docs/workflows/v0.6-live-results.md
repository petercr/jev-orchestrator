## Findings and follow-up

Source inspection confirmed that resume changed a recorded successful worker
outcome to `ok: false`. The resumed display consequently called an exit-0
attempt unsuccessful. Invalidating validation does not require falsifying the
historical process result. The fix retains the actual outcome while still
discarding old reads, validation, and worker-modified-file attribution, and
replacing the worker summary with an explicit earlier-segment notice.

The read selector also put generic metadata before known files explicitly
named by the task. The fix keeps required root instructions and search evidence
first, then prefers known task files over generic metadata. Every chosen file
still passes the existing path and secret-file checks and requires approval.
It does not authorize FINISH, alter assessments, increase limits, or infer task
acceptance. Deterministic regressions cover the changed context and selection;
a fresh live cohort is needed to establish the resulting workflow.

These observations identify concrete context and file-selection problems; they
do not establish a statistical routing failure rate or prove that the fixes
will produce a successful live completion. The original archive, protocol,
fixtures, patched worktree, raw PTYs, traces, saved records, hash comparisons,
and process/oracle inspections remain under
`/home/peterc/.cache/dev-v06-pilot-20261023`. Its `results.json` and
`cohort-status.json` record the failed required scenario and unused slots.

The release stays blocked pending the
[separately identified retest](v0.6-live-retest-amendment.md) and operator
acceptance. The original observation must remain visible alongside any later
result.
