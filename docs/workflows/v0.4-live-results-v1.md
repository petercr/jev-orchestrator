# v0.4 bounded live comparison — results v1

The eight-launch pilot produced seven accepted patches and seven approved loop
completions. One launch exited before evaluation because of an entry-point
symlink problem and remains an unsuccessful observation. The live pairs show
no reduction in manual routing; they do not establish a reliability or speed
improvement over v0.3.1. Both actual staged repairs succeeded, but neither needed
the new high-testing-score policy exception. That improvement is supported by
the separately labeled deterministic workflow regressions.

Collection ran on 2026-10-18, 20:23–20:35 America/New_York
(2026-10-19 00:23–00:35 UTC), under [protocol v1](v0.4-live-protocol-v1.md)
and its [entry-point amendment](v0.4-live-protocol-amendment.md). No failed
observation was replaced, no extra cohort was added, and assessments were not
renormalized. This report covers the bounded pilot; release packaging remains
the next step.

## Repair and evaluation recovery

Both first repair calls honored staging: only regression cases were added and
the implementation hash remained original. Each independently approved test
then failed on the actual empty-label bug. A second approved Codex call fixed
the implementation while retaining the regression cases. Fresh test and lint
passed in generation 2 before completion review.

The baseline repair recommendation had `needsTesting=0.43`, worker probability
0.73, and confidence 0.70. After recovery, the candidate's recommendation had
`needsTesting=0.42`, worker probability 0.71, and confidence 0.67. Both followed
the ordinary permitted worker route; neither trace contains the new exception's
policy reason. Do not claim the new repair exception improved this live pair.

In r06 iteration 4 and r07 iteration 2, TypeSafe returned a distribution totaling
0.99. The existing 0.001 tolerance rejected each response at `distribution/sum`.
Each run received the protocol's one explicit continuation; evidence, selected
worker, consumed iterations, and remaining calls survived. No action or approval
was fabricated for the failed evaluation. r06 finished at iteration eight,
leaving no spare iteration. The extra candidate iterations in the repair and
Claude pairs reflect these observed evaluation failures; they do not prove a
runtime regression or improvement.

## Instrument limitations and supplemental audit

r01 used a pnpm-symlinked entry-point path. Node resolved it, while the packaged
CLI's direct-invocation guard compared the unresolved argument; the process
exited before invoking the CLI. The amendment switched only remaining entry
paths to their real paths and retained original protocol bytes/checksum. There
is consequently no baseline TypeSafe/Codex/tags observation and no complete core
matrix. A new matching observation would require a newly recorded budget.

\* In r05 and r06, the bounded trace serialized validation script labels in
`stateAfter.evidence.validations` as `[TRUNCATED]`. The frozen inspector requires
those exact labels and therefore conservatively reports `independentlyPassed`
and `acceptedPatch` as false. Raw inspections and `results.json` retain that
result. It is insufficient snapshot evidence, not a failed final check.

A separately labeled post-observation [receipt audit](../../scripts/workflows/receipts.mjs)
requires actual approved package-script receipts in the current generation,
zero exits without timeout, and the matching complete final validation summary.
For r05 those are iterations 5/test and 6/lint; for r06 they are iterations
6/test and 7/lint, all generation 2. Both final summaries name test and lint as
passed, with no omitted requirements or pending refresh. Final inspection
hashes, allowed scope, examples, and approved FINISH also match. Those receipts
support the two audited accepted-patch classifications above. The supplemental
reader runs no tools or models and does not change execution or recorded traces.

The v0.4 release description should claim clearer operator explanations and a
focused deterministic repair-policy correction. It should disclose remaining
manual routing and reject any claim that this pilot proved fewer live detours,
better completion rates, or faster execution. The missing cell and trace-label
limitation remain documented follow-ups; neither justifies changing confidence,
permissions, validation, or approval requirements.
