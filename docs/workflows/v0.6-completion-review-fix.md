# v0.6 completion review during validated inspection

The [2026-10-28 retest](v0.6-live-retest-results-20261028.md) remains a failed
required live observation. Claude's implementation passed the external oracle
and fresh independent validation, but the saved task exhausted eight iterations
without acceptance. The active-worker interruption scenario remains unlaunched.
This offline follow-up does not change that outcome or clear the release gate.

The retained trace shows the concrete sequence: root instructions on iteration
1, approved Claude alternative on 2, malformed evaluation and explicit recovery
on 3, clean stop before validation on 4, then instruction reread on 5, passing
validation on 6, and clear `READ_FILE` routes on 7 and 8. The task-completion
probabilities for those final reads were 0.29 and 0.28. Manual `FINISH` was
unavailable because the model requested neither completion nor redundant tests.

## Correction

Policy keeps a clear `READ_FILE` recommendation as the proposed action. It may
also offer explicit completion review when a worker attempt exists and every
required check passed independently in the current generation after that
attempt. Declared workflow coverage still applies. Worker claims, baseline-only
checks, checks from before the attempt, future checks, and stale generations
cannot establish eligibility.

The operator can approve the read as before, or independently review the saved
changes against the original task and select `FINISH`. The resolved completion
candidate requires its own approval. The policy trace records
`completionReview: validated_inspection` and both operator decisions. Final
approval rechecks validation, worker evidence, and required preparation.

Repository-refresh failures, missing issue/instruction context, omitted checks,
ambiguous routing, and high missing-information/stuck assessments still block
this route. A worker repair recommendation remains a worker route. Automatic
completion retains its 95% threshold. Remaining iterations do not grant review
eligibility, reset calls, or extend the eight-iteration limit.

## Offline evidence

Focused policy and orchestration regressions exercise both worker selections,
post-attempt validation ordering and workflow coverage, default read execution,
and rejection, stop, interruption, or invalidated evidence at final approval.
The presentation test confirms the read and optional acceptance are explained
without changing the approval data.

`src/saved-runs/completion.test.ts` reproduces the recovery/stop/resume sequence
for Codex and Claude using synthetic provider/worker boundaries, real Git and
durable saved records, real bounded reads, and a real independent `npm test`.
It selects and separately approves acceptance on iteration 8, retains exactly
one worker attempt, and proves the rejected evaluation created no approval.
This is deterministic regression evidence, not a replacement live observation.

Full verification results will be recorded after the final checks. Further
live collection requires an identified installed candidate, a frozen amendment,
and operator authorization under the existing protocol. Publication remains
separately gated.
